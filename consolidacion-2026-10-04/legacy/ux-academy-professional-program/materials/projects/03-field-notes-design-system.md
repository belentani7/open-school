# Project 3 — Field Notes Design System

## Context

Field Notes is a collaborative product for teams who record field observations, attach media, tag findings and prepare a shared readout. The product is expanding from a small internal tool to several teams with different workflows.

## Challenge

Create the foundations and a small but robust component library that supports capturing an observation, adding a tag, handling an upload state, reviewing a finding and navigating a collection. The goal is not a catalogue of every possible component; it is a documented system that teams can extend responsibly.

| Milestone | Required artifact | Review question |
|---|---|---|
| Foundations | Primitive and semantic tokens | Does naming express purpose rather than a particular hex value? |
| Components | Anatomy, variants and interaction states | What belongs in one component set and what does not? |
| Accessibility | Keyboard, focus, feedback and content rules | Can each state be perceived and operated? |
| Responsive behavior | Component resizing and composition rules | What is the intended behavior under constraint? |
| Governance | Contribution, versioning and deprecation proposal | How can a team change the system without creating fragmentation? |

## Success criteria

The system includes color, typography, spacing, shape or elevation decisions; a minimum of four documented components; states for loading, error, empty and disabled where relevant; semantic naming; and a governance proposal.

## Assessment

Use the **Design Systems**, **UI Design**, **Accessibility**, **Responsive & Mobile UX**, and **Documentation** rubrics. The submission must show the connection between a token, a component property and a real interface use.
