Definición oficial (síntesis educativa)

In-App Billing y subscriptions — Billing Library 6. Esta síntesis educativa resume la guía oficial sin reproducir texto propietario literal. Para el texto normativo completo, consulta la referencia oficial enlazada.

Definición operativa: En Android, in-app billing y subscriptions se implementa siguiendo los principios de compatibilidad (API level + CTS), seguridad por defecto y performance medible. El contrato se expresa en manifiestos, tipos y permisos, no solo en documentación narrativa.

Ejemplo práctico (Kotlin + Compose)

Ejemplo original y ejecutable que ilustra el patrón. No es copia de samples propietarios; está creado para esta plataforma.

class inappbillingViewModel @Inject constructor(
  private val repo: Repo
) : ViewModel() {
  val uiState = repo.flow
    .map { UiState(it) }
    .stateIn(viewModelScope, WhileSubscribed(5000), UiState())
}
Buena práctica: Usa remember, StateFlow y repeatOnLifecycle para un ciclo de vida correcto. Mide con Macrobenchmark y Perfetto.

Protocolos, lenguajes y criterios aplicables

  • Lenguajes: Kotlin (oficial), Java 8+ desugared, SQL (Room), Protobuf/GraphQL para red.
  • Protocolos: HTTPS/TLS 1.3, HTTP/2, gRPC, WebSocket/SSE, BLE GATT, NFC NDEF, MQTT.
  • Criterios: Permisos runtime 13/14, NSC, Keystore/StrongBox, Baseline Profiles, accesibilidad.

Mini-quiz

¿Qué valida CTS?

Que el dispositivo cumple el CDD y APIs públicas se comportan como especifica AOSP.

¿Cuándo usar WorkManager vs FGS?

WorkManager para trabajo deferrable garantizado; FGS para trabajo inmediato visible al usuario con notificación.
