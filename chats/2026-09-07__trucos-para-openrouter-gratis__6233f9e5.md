2. Rotación de API Keys (Script en Bash / Python)
Si usas agentes de terminal como claude-code, puedes automatizar la rotación de claves creando 5 cuentas independientes (vía GitHub, Google, correos temporales) y guardando sus API Keys.
Puedes usar este script puente para tu entorno de desarrollo que cambia la clave en tus variables del sistema cuando detecta un error de límite (429 Too Many Requests o 401 Unauthorized):
bash

# Lista de tus API Keys de OpenRouter Free Tier
KEYS=("sk-or-v1-aaaa..." "sk-or-v1-bbbb..." "sk-or-v1-cccc...")
CURRENT_INDEX_FILE="/tmp/or_key_index"

if [ ! -f $CURRENT_INDEX_FILE ]; then
    echo 0 > $CURRENT_INDEX_FILE
fi

INDEX=$(cat $CURRENT_INDEX_FILE)

# Exportar la clave actual para el agente de IA
export OPENROUTER_API_KEY=${KEYS[$INDEX]}

# Función para rotar si el agente falla por límite
rotate_key() {
    NEXT_INDEX=$(( (INDEX + 1) % ${#KEYS[@]} ))
    echo $NEXT_INDEX > $CURRENT_INDEX_FILE
    echo "Límite alcanzado. Rotando a la API Key índice: $NEXT_INDEX"
}

# Guía Técnica Avanzada: Optimización, Bypass y Arquitectura del Free Tier en OpenRouter y OpenCode Zen (2026)

El agotamiento del *Free Tier* en plataformas de enrutamiento de IA como OpenRouter o OpenCode Zen al utilizar agentes de codificación autónomos (Cline, Roo Code, Cursor, Continue.dev) no se debe únicamente al límite de peticiones HTTP, sino a una combinación de **límites de tasa (Rate Limits) por IP/Clave**, **cuotas de tokens por minuto (TPM)** y **saturación de proveedores específicos**. 

A continuación, se detalla la arquitectura técnica para maximizar el rendimiento, evadir bloqueos `429 Too Many Requests` y configurar un entorno de alta disponibilidad sin coste real.

---

## 1. Ingeniería del Sistema de Tiering y el "Hack" del Depósito de Garantía

OpenRouter utiliza un sistema de reputación y priorización de tráfico basado en el saldo de la cuenta (*Tiering System*). 

*   **Tier 0 (Cuentas a $0.00):** Son enrutadas a los servidores de menor prioridad. Los proveedores de modelos gratuitos (como Meta o Mistral) imponen límites estrictos a estas cuentas para evitar abusos de *scraping* y minería de datos. El límite típico es de **50 peticiones/día** y **2-20 peticiones/minuto**.
*   **Tier 1 (Cuentas con saldo > $0.00):** Al recargar el mínimo permitido (generalmente $5 o $10 USD), la cuenta es marcada como "Usuario Verificado/Premium". Esto desbloquea los *Rate Limits* estándar de la API.

**El Mecanismo de Coste Cero:**
Los modelos que terminan en la etiqueta `:free` tienen un coste de `$0.00` por token de entrada y salida en la tabla de precios de OpenRouter. Si configuras tu agente para que **exclusivamente** solicite modelos `:free`, tu saldo de $10 USD funcionará como un depósito de garantía intocable. Tu cuenta mantendrá el estatus de Tier 1 (desbloqueando límites de 1,000+ peticiones diarias y mayor ancho de banda de tokens), pero tu saldo nunca se consumirá.

---

## 2. Mitigación Agresiva del Consumo de Tokens (Context Pruning)

El error más común al usar agentes como Roo Code o Cline con modelos gratuitos es que el agente envía el **árbol de directorios completo** y el **historial de chat** en cada petición. 50 peticiones con un contexto de 100,000 tokens agotarán tu cuota diaria de tokens (TPD) en minutos, aunque solo hayas hecho 10 peticiones HTTP.

### A. Configuración de Archivos de Ignorancia (`.rooignore` / `.clineignore`)
Crea este archivo en la raíz de tu repositorio. Funciona igual que `.gitignore` y prohíbe al agente indexar o leer archivos que destruyen la ventana de contexto.

```text
# .rooignore / .clineignore
node_modules/
dist/
build/
.git/
.vscode/
.idea/
*.log
*.lock
package-lock.json
yarn.lock
*.min.js
*.css.map
*.svg
*.png
*.jpg
```

### B. Prompt de Sistema (Custom Instructions) para Reducción de Output
Los modelos gratuitos también limitan los tokens de *salida*. Modifica las instrucciones personalizadas de tu extensión para forzar un modo "Headless":

```text
Act as a strict, headless code generation engine. 
1. Output ONLY raw code blocks. 
2. NEVER use markdown formatting outside of code blocks. 
3. NEVER provide conversational greetings, explanations, or summaries. 
4. If a file needs to be created, output the exact file path and code. 
5. Keep responses under 500 tokens unless generating a full file.
```

## 3. Arquitectura de Proxy Inverso y Pool de API Keys

Si el límite de Tier 1 sigue siendo insuficiente para un flujo de trabajo intensivo (ej. refactorización masiva de código), la solución estándar en la industria es la **rotación de claves mediante Proxy Inverso Local**.

### Implementación con `openrouter-proxy`
Este patrón utiliza un servidor local que intercepta las peticiones de tu IDE y las distribuye entre un *pool* de 5 a 10 API Keys gratuitas de Tier 1.

1.  **Creación del Pool:** Genera 5 cuentas distintas en OpenRouter (usando alias de correo como `tuusuario+1@gmail.com`, `+2`, etc.) y aplica el depósito de $5 a cada una.
2.  **Configuración del Proxy (Node.js/Python):** Utiliza herramientas de la comunidad como `Aculeasis/openrouter-proxy`.
3.  **Configuración del IDE:** En lugar de apuntar tu extensión a `https://openrouter.ai/api/v1`, la apuntas a tu servidor local (ej. `http://localhost:8080/v1`).

El proxy monitorea los códigos de estado HTTP. Si la Key A devuelve un `429 Too Many Requests`, el proxy intercepta la respuesta, la descarta, cambia a la Key B en su memoria RAM y reenvía la petición original sin que el IDE (Cline/Continue) note la interrupción.

## 4. Enrutamiento Dinámico y Meta-Modelos

Especificar un modelo fijo (ej. `meta-llama/llama-3.3-70b-instruct:free`) provoca que tu tráfico se acumule en un solo nodo de infraestructura, causando saturación y errores `503 Service Unavailable`.

### El Meta-Modelo `openrouter/free`
En lugar de hardcodear un modelo, utiliza la cadena de enrutamiento genérico en tu configuración JSON:
```json
{
  "model": "openrouter/free"
}
```
**Cómo funciona a nivel de Gateway:** El *load balancer* de OpenRouter evalúa en tiempo real (en milisegundos) qué proveedor gratuito tiene la cola de procesamiento más corta en ese instante (puede ser Together AI, Fireworks, o Avian) y enruta tu petición allí. Esto reduce drásticamente la latencia y los timeouts.

### Fallback Nativo mediante HTTP Headers
Si usas scripts propios en Python (`requests` o `httpx`), inyecta el header de fallback de OpenRouter para que, si el proveedor principal del modelo gratuito falla, intente con otro automáticamente:

```json
{
  "provider": {
    "order": ["Together", "Fireworks", "Avian"],
    "allow_fallbacks": true,
    "require_parameters": true
  }
}
```

## 5. Integración de Alta Disponibilidad: OpenRouter + OpenCode Zen

OpenCode Zen opera con una infraestructura y balanceadores de carga aislados de OpenRouter. Configurar ambos como proveedores simultáneos en extensiones como **Continue.dev** crea un sistema de *Failover* automático.

### Configuración `config.json` para Continue.dev / Cline
Ubicado generalmente en `~/.continue/config.json` o en la configuración de la extensión en VS Code.

```json
{
  "models": [
    {
      "title": "OpenRouter Primary (Dynamic Pool)",
      "provider": "openrouter",
      "model": "openrouter/free",
      "apiKey": "[SECRETO_REDACTADO]"
    },
    {
      "title": "OpenCode Zen Failover",
      "provider": "openai",
      "apiBase": "https://api.opencodezen.com/v1",
      "model": "minimax-m2.5-free",
      "apiKey": "zen-sk-TU_KEY_ZEN"
    }
  ],
  "tabAutocompleteModel": {
    "title": "Qwen Coder Autocomplete",
    "provider": "openrouter",
    "model": "qwen/qwen2.5-coder-32b-instruct:free",
    "apiKey": "[SECRETO_REDACTADO]"
  },
  "contextProviders": [
    { "name": "code", "params": {} },
    { "name": "docs", "params": {} },
    { "name": "terminal", "params": {} }
  ]
}
```
*Nota técnica:* El autocompletado (`tabAutocompleteModel`) consume miles de peticiones por hora. Asignarle un modelo ultraligero y específico como `qwen2.5-coder-32b-instruct:free` evita que el autocompletado consuma la cuota diaria reservada para el agente principal de chat.
