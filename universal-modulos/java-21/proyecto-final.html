Conceptos y decisiones

Requisitos y alcance

Construye un catálogo de cursos con identificador, título, duración y etiquetas. El usuario puede buscar y filtrar, abrir una ficha y consultar una API read-only. No prometas matrícula, certificación oficial ni cuentas si no las implementas. Define las rutas y criterios de aceptación antes de programar.

Arquitectura y etapas

Primero modela Course con invariantes y un repositorio en memoria. Después crea un servicio de búsqueda, controlador HTTP y frontend con HTML semántico. Añade persistencia opcional mediante un repositorio separado, migraciones y pruebas de integración. El navegador no necesita acceso directo a la base de datos.

Evaluación y entrega

La entrega incluye código fuente, README reproducible, pruebas de datos inválidos y búsqueda, build del JAR, healthcheck real y un registro de los resultados. Comprueba teclado, foco visible, errores de red y móvil. Publica solo tras comprobar datos públicos y no expongas un directorio privado.

Laboratorio práctico

Entrega un repositorio con las capas dominio, aplicación e infraestructura. Implementa al menos cinco cursos de ejemplo declarados como datos sintéticos, GET /api/v1/courses, GET /actuator/health y una interfaz que informa si falla la red.

Solución y criterios de aceptación

Rúbrica: 25% dominio y validación; 20% API y contratos; 20% pruebas verificables; 20% interfaz y accesibilidad; 15% documentación y entrega. Exige evidencia de cada apartado; no se otorga una acreditación oficial.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.
