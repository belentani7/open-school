SQL, JDBC y persistencia JPA

Objetivo: aplicar sql, jdbc y persistencia jpa mediante conceptos, código de referencia, práctica y verificación.

TeoríaEjemploLaboratorioEvaluación

Conceptos y decisiones

Modelo relacional

Una clave primaria identifica filas y una clave foránea representa una relación. NOT NULL, UNIQUE y CHECK protegen invariantes incluso si otra aplicación escribe. Un índice acelera ciertas consultas, pero ocupa almacenamiento y añade coste a escrituras.

Consultas parametrizadas

PreparedStatement separa datos de SQL. Los parámetros no sustituyen nombres de columnas o direcciones de orden: para esos casos usa una lista permitida. Nunca concatenes una entrada no confiable a una consulta.

Transacciones y migraciones

Agrupa operaciones que deben cumplirse juntas en una transacción. JPA gestiona entidades y sincroniza cambios; evita N+1 y carga perezosa accidental al serializar. En producción, aplica migraciones versionadas y usa validación de esquema, no create-drop sobre datos persistentes.

Ejemplo comentado en el módulo

Lee el código y relaciónalo con la teoría. Los ejemplos con bibliotecas externas requieren el proyecto indicado; los fragmentos no se presentan como aplicaciones autónomas.

import java.sql.*;
class CourseQueries {
    static String findTitle(Connection connection, String id)
            throws SQLException {
        try (var ps = connection.prepareStatement(
                "SELECT title FROM courses WHERE id = ?")) {
            ps.setString(1, id);
            try (var rs = ps.executeQuery()) {
                return rs.next() ? rs.getString("title") : null;
            }
        }
    }
}

Laboratorio práctico

Usa una base H2 de pruebas con tabla courses(id varchar primary key, title varchar not null). Inserta un registro y prueba findTitle con clave válida, desconocida y texto con comillas.

Solución y criterios de aceptación

El parámetro se trata como dato literal. Para una clave desconocida se devuelve null en este ejemplo; una API de dominio puede convertirlo a Optional. Cierra conexiones mediante el propietario del DataSource.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.
