Objetos, records e invariantes

Objetivo: aplicar objetos, records e invariantes mediante conceptos, código de referencia, práctica y verificación.

TeoríaEjemploLaboratorioEvaluación

Conceptos y decisiones

Encapsulación

Un objeto no es solo una bolsa de campos: protege reglas del dominio. Un constructor comprueba entradas y los métodos evitan estados inválidos. La visibilidad private reduce el acoplamiento. No confundas getters y setters indiscriminados con encapsulación.

Records e inmutabilidad

Un record genera constructor, accesores, equals, hashCode y toString. Es adecuado para datos de valor y DTO. La inmutabilidad es superficial: si almacenas una lista mutable, copia sus elementos con List.copyOf. La validación puede escribirse en el constructor compacto.

Interfaces y composición

Una interfaz representa un contrato. La composición permite intercambiar implementaciones sin heredar comportamiento accidental. Un servicio recibe su dependencia por constructor. Las clases selladas son útiles cuando el conjunto de variantes es deliberadamente cerrado, no para toda jerarquía.

Ejemplo comentado en el módulo

Lee el código y relaciónalo con la teoría. Los ejemplos con bibliotecas externas requieren el proyecto indicado; los fragmentos no se presentan como aplicaciones autónomas.

public record Course(String id, String title, int hours) {
    public Course {
        if (id == null || id.isBlank() || title == null || title.isBlank())
            throw new IllegalArgumentException("Missing course data");
        if (hours <= 0) throw new IllegalArgumentException("Invalid hours");
    }
}

Laboratorio práctico

Crea Course.java, añade un catálogo con dos registros y verifica que rechaza un curso de cero horas. Define una interfaz CourseRepository con una operación findAll.

Solución y criterios de aceptación

El constructor compacto valida antes de asignar los componentes. Una implementación en memoria de CourseRepository puede devolver List.copyOf de su colección.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.

Autoevaluación

¿Un record con una lista mutable es profundamente inmutable?

Solución razonadaNo. El record no copia automáticamente sus componentes mutables.
¿Qué permite intercambiar repositorios sin modificar el servicio?

Solución razonadaUna interfaz. La dependencia contra una abstracción separa contrato e implementación.
