Seguridad defensiva y privacidad

Objetivo: aplicar seguridad defensiva y privacidad mediante conceptos, código de referencia, práctica y verificación.

TeoríaEjemploLaboratorioEvaluación

Conceptos y decisiones

Identidad y autorización

Autenticación confirma identidad; autorización comprueba si puede realizar una acción sobre un recurso concreto. Deniega por defecto y concede permisos mínimos. No confíes en un rol declarado por el cliente. Comprueba la propiedad de cada recurso.

Entradas y respuestas

Valida estructura, tamaño y límites. Escapa datos según el contexto al renderizar HTML. CORS controla lectura de respuestas por navegadores, pero no sustituye autenticación. CSRF protege operaciones con credenciales que el navegador adjunta automáticamente; no desactives sin comprender el modelo.

Secretos y datos

Usa variables de entorno o gestores de secretos, nunca credenciales dentro de commits. Las contraseñas requieren algoritmos diseñados para hashing de contraseñas y sal. Define retención, borrado y mínimo de registros. Las pruebas usan datos sintéticos.

Ejemplo comentado en el módulo

Lee el código y relaciónalo con la teoría. Los ejemplos con bibliotecas externas requieren el proyecto indicado; los fragmentos no se presentan como aplicaciones autónomas.

import org.springframework.context.annotation.*;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;
@Configuration
class SecurityConfig {
    @Bean SecurityFilterChain rules(HttpSecurity http) throws Exception {
        return http.authorizeHttpRequests(a -> a
            .requestMatchers("/actuator/health").permitAll()
            .anyRequest().denyAll()).build();
    }
}

Laboratorio práctico

En un servicio de pruebas, permite solo el endpoint de salud y verifica que las rutas administrativas permanecen bloqueadas. Después diseña permisos explícitos para el catálogo de solo lectura.

Solución y criterios de aceptación

Conserva denyAll como regla final. Autoriza únicamente GET sobre el catálogo; verifica otros métodos y rutas mediante pruebas de integración. No expongas detalles de salud.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.

Autoevaluación

¿CORS sustituye autenticación?

Solución razonadaNo. CORS es una política de navegador, no un control de identidad.
¿Dónde deben mantenerse credenciales de producción?

Solución razonadaGestor de secretos o entorno protegido. Mantén secretos fuera del historial.
