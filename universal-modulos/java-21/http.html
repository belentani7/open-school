HTTP, REST y Spring Boot

Objetivo: aplicar http, rest y spring boot mediante conceptos, código de referencia, práctica y verificación.

TeoríaEjemploLaboratorioEvaluación

Conceptos y decisiones

Recursos y contratos

Una API REST organiza recursos con identificadores estables. GET debe ser seguro respecto a cambios del servidor; POST crea o procesa; PUT reemplaza de forma idempotente si se implementa su semántica. Usa 400 para entrada incorrecta, 404 para ausencia y 409 para conflictos reales.

Controlador y servicio

El controlador convierte HTTP en una llamada de aplicación. El servicio implementa reglas de negocio y el repositorio accede a datos. Devuelve DTO, no entidades JPA con relaciones o campos sensibles. La validación de parámetros pertenece a la frontera.

Paginación y errores

Limita tamaño de página y ordena de forma estable. Para grandes catálogos, considera cursores. Un endpoint de salud no debe revelar credenciales, rutas o infraestructura privada. Describe contratos de error y prueba las respuestas con un cliente HTTP.

Ejemplo comentado en el módulo

Lee el código y relaciónalo con la teoría. Los ejemplos con bibliotecas externas requieren el proyecto indicado; los fragmentos no se presentan como aplicaciones autónomas.

import org.springframework.web.bind.annotation.*;
import java.util.*;
@RestController
@RequestMapping("/api/v1/courses")
class CourseController {
    record CourseView(String id, String title) {}
    private final List<CourseView> courses =
        List.of(new CourseView("java", "Java 21"));
    @GetMapping
    List<CourseView> all(@RequestParam(defaultValue="") String q) {
        return courses.stream().filter(c -> c.title()
            .toLowerCase(Locale.ROOT).contains(q.strip()
            .toLowerCase(Locale.ROOT))).toList();
    }
}

Laboratorio práctico

En un proyecto Spring Boot con starter-web, crea un controlador que permita buscar cursos. Añade límite de consulta, DTO y tests MockMvc. Prueba búsqueda vacía, coincidencia y consulta demasiado larga.

Solución y criterios de aceptación

Devuelve 200 con una lista, aunque esté vacía. Una consulta inválida devuelve 400. No serialices entidades de usuario. MockMvc debe comprobar código y estructura JSON.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.
