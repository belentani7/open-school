Excepciones, validación y recursos

Objetivo: aplicar excepciones, validación y recursos mediante conceptos, código de referencia, práctica y verificación.

TeoríaEjemploLaboratorioEvaluación

Conceptos y decisiones

Errores recuperables

Las excepciones checked deben declararse o capturarse; IOException es un ejemplo. RuntimeException suele señalar una violación de contrato o fallo no recuperable localmente. Captura solo cuando puedas recuperar, traducir o añadir contexto; no silencies errores.

Try-with-resources

Los recursos AutoCloseable se cierran automáticamente al salir del bloque, también si hay una excepción. No dependas del recolector para cerrar archivos, conexiones o streams. Mantén una frontera clara entre la lógica y los recursos de infraestructura.

Validación y diagnóstico

Valida límites al recibir datos externos. No registres contraseñas, tokens ni documentos privados. Las excepciones del dominio deben tener mensajes útiles para el equipo y una traducción controlada al usuario. No devuelvas stack traces en HTTP.

Ejemplo comentado en el módulo

Lee el código y relaciónalo con la teoría. Los ejemplos con bibliotecas externas requieren el proyecto indicado; los fragmentos no se presentan como aplicaciones autónomas.

import java.io.*;
import java.nio.file.*;
public class Main {
    static long countLines(Path file) throws IOException {
        try (var reader = Files.newBufferedReader(file)) {
            return reader.lines().count();
        }
    }
    public static void main(String[] args) {
        if (args.length != 1) return;
        try { System.out.println(countLines(Path.of(args[0]))); }
        catch (IOException ex) {
            System.err.println("Cannot read file");
        }
    }
}

Laboratorio práctico

Escribe un lector de configuración que rechace campos ausentes y capture únicamente los fallos de lectura en su frontera. Prueba un archivo inexistente y otro válido.

Solución y criterios de aceptación

Separa IOException de IllegalArgumentException. El lector utiliza try-with-resources; la validación reporta el campo incorrecto sin volcar el contenido sensible.

Guarda el código, el comando utilizado y el resultado de las pruebas como evidencia personal.

Autoevaluación

¿Qué garantiza try-with-resources?

Solución razonadaCierre de recursos incluso con excepción. El cierre está gestionado por el lenguaje.
¿Qué se debe enviar al cliente ante un error inesperado?

Solución razonadaMensaje controlado y referencia de diagnóstico. Evita exponer información interna.
